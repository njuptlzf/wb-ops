## v0.17 · 进行中

### 锚点扩行：严重错误行的上下文连续保留 ✅ 已实现（2026-11-06）

**问题**：`stack-trace` 场景下，`FATAL: unhandled rejection` 这类行能命中关键词被保留，
但紧随其后的堆栈帧（`    at Worker.run (/srv/worker.js:120:22)`）不含关键词，全部落入落盘文件。
结果是：上下文里留了"哪里炸了"，却丢了"怎么炸的"——排查失败时模型必须多读一次落盘文件。

**做法**：命中严重错误（`FATAL/ERROR/Exception/Traceback/panic/segmentation/core dumped/abort/
assertion/错误/异常/崩溃/致命`）的行，在预算内顺带保留其后若干连续行（默认 4 行）。

**配套的三处加固**（没有这三步，扩行会引入新问题）：

| 问题 | 对策 |
|---|---|
| 均匀撒点会把连续堆栈帧打散成孤立的单行 | 抽样改为**按连续块**进行，块整块保留、块内再均匀采样 |
| 关键行独占预算会把尾部挤出预算 → 尾部硬截断丢掉 `Exit Code` 行 | 关键行加**字节配额**（占预算 42%），超额时锚点块优先、其余整块丢弃 |
| 满屏错误时无限扩行 | 锚点扩行总量护栏（60 行）+ 关键行条数上限（40 条）仍在 |

**验收**：`test/register.test.ts` 新增 3 项（扩行生效 / 护栏生效 / 不挤掉 Exit Code），
`test/benchmark.mjs` 的 `stack-trace` 夹具期望信息保留率从 **2/6 → 6/6**。

### P1 · 影响覆盖面

- [ ] **宿主 8KB 落盘天花板**——宿主 `persisted-output` 阈值 ≈8KB 是硬天花板：超过它宿主先
      落盘，mod 看不到原文。因此 mod 的实际收益上限 = (预算, 8KB) 区间 + 宿主未落盘的其余工具。
      这是**宿主侧的限制，插件层无法突破**，只有等宿主提高阈值才能受益。
      **验收**：宿主阈值提高后，回归 benchmark 确认大输出命中率提升。
- [ ] **`WB_OPS_STATS=0` 与 MCP 的联动**——当前不联动（关掉统计时工具仍在，数据为空时如实
      返回「还没有记账数据」）。可考虑关统计时同步隐藏工具，减少工具清单噪音。
      **验收**：设 `WB_OPS_STATS=0` 后工具清单里不再出现报表工具。

### P2 · 体验与打磨

- [ ] **看板的"模型维度"视图增强**——当前只有模型 × 事件时间轴，可加"同一模型在不同会话
      的省量对比"，便于判断换模型是否真的更省。
- [ ] **压缩摘要的可读性**——标记行目前是 `[wb-ops] 已省略 N 行 · 原文 XKB≈Yk tok → ≈Z tok（省 P%）
      · 落盘 <path>`。可以考虑按出口类型给出不同的措辞（如 Read 场景提示"可回看: Read offset="），
      让模型更容易理解该如何取回被省略的部分。
- [ ] **基准夹具扩充**——目前 9 个夹具覆盖 shell / grep / read / webfetch 四类出口。可增加
      PowerShell 输出（Windows 特有）、MCP 工具兜底输出、二进制/超长单行等边界场景。

## 长期方向

- **压缩质量的可量化跟踪**——把 `--qa` 探针评测接入 CI，用固定的模型 + 固定的题集持续跟踪
  "压缩后可用性"，让算法改动有客观依据而非手感判断。
- **落盘内容的分层保留**——目前超限原文整文件落盘。可探索"只存最长空洞段 + 关键行"的
  分层策略，减少磁盘占用。
- **多端统计**——当前按 session 记账，跨设备（本地 + 远程会话）的会话标题与统计尚未合并。
